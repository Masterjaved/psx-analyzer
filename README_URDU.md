# PSX سٹاک تجزیہ کار — Netlify ورژن (سیٹ اپ ہدایات)

اب یہ ایک ہی فولڈر ہے، بالکل AzeemiHub کی طرح — یہ پورا فولڈر Netlify پر ڈالیں، فرنٹ اینڈ اور بیک اینڈ دونوں ایک ہی جگہ سے کام کریں گے۔

## کیا ملا ہے
```
psx-netlify/
  public/                ← ویب سائٹ (صرف یہی فولڈر عوام کو نظر آتا ہے)
    index.html, portfolio.html, admin.html
    app.js, auth.js, esc.js, manifest.json, sw.js, icon-*.png
  netlify/functions/     ← "بیک اینڈ" — PSX ڈیٹا، انڈیکیٹرز، AI تجزیہ، الرٹ (سب یہاں)
  supabase/migrations/   ← Phase 2 کے لیے ڈیٹابیس SQL (ابھی استعمال میں نہیں)
  tests/                 ← خودکار ٹیسٹ (npm test)
  netlify.toml           ← Netlify کو بتاتا ہے سب کیسے جوڑنا ہے
  package.json           ← ضروری npm پیکج کی فہرست
  .env.example           ← تمام environment variables کی فہرست (اصل keys کبھی یہاں نہ لکھیں)
```

## قدم 1 — Netlify پر اپلوڈ کرنا

اگر آپ کی AzeemiHub سائٹ پہلے سے **GitHub** سے جڑی ہے (یعنی Git کے ذریعے ڈیپلائے ہوتی ہے)، تو یہی سب سے آسان طریقہ ہے:

1. `github.com` پر ایک نئی ریپوزٹری بنائیں (مثلاً `psx-analyzer`)
2. اس فولڈر کی تمام فائلیں اس ریپو میں اپلوڈ کریں (GitHub کی ویب سائٹ پر "Add file → Upload files" سے بھی ہو جاتا ہے، کمانڈ لائن کی ضرورت نہیں)
3. `app.netlify.com` پر جائیں → **"Add new site" → "Import an existing project"**
4. GitHub منتخب کریں، وہی `psx-analyzer` ریپو چنیں
5. Netlify خودکار پہچان لے گا (build settings خالی چھوڑ سکتے ہیں، ہمارا `netlify.toml` سب بتا دیتا ہے)
6. **Deploy site** دبائیں — چند منٹ میں لنک مل جائے گا، مثلاً `psx-analyzer-xyz.netlify.app`

> ⚠️ **اپڈیٹ (Phase 1):** ویب سائٹ کی فائلیں اب `public/` فولڈر میں ہیں۔ اگر آپ کے GitHub ریپو میں پرانی ورژن کی فائلیں (ریپو کے اوپری لیول پر `index.html`, `app.js`, `auth.js`, `admin.html`, `portfolio.html`, `manifest.json`, `sw.js`) ہیں تو نئی فائلیں اپلوڈ کرنے کے بعد وہ پرانی فائلیں **حذف کر دیں** — ورنہ ریپو میں دو نقلیں پڑی رہیں گی (سائٹ صرف `public/` والی دکھائے گی)۔

> اگر آپ کی موجودہ سائٹ GitHub سے نہیں جڑی بلکہ سیدھا فولڈر گھسیٹ (drag & drop) کر کے اپلوڈ ہوتی ہے، تو Functions کے لیے GitHub والا طریقہ ہی استعمال کرنا پڑے گا — صرف فولڈر ڈریگ کرنے سے functions فعال نہیں ہوتے۔

## قدم 2 — اپنی API keys ڈالنا (بہت ضروری)

آپ کی keys کہیں بھی کوڈ کی فائل میں نہیں لکھنی — یہ Netlify کی اپنی محفوظ سیٹنگز میں ڈالی جاتی ہیں:

1. Netlify ڈیش بورڈ میں اپنی سائٹ کھولیں
2. **Site configuration → Environment variables** پر جائیں
3. **"Add a variable"** پر کلک کر کے یہ سب ایک ایک کر کے ڈالیں:

| Key کا نام | کیا ڈالنا ہے |
|---|---|
| `ANTHROPIC_API_KEY` | آپ کی نئی Claude API key |
| `GEMINI_API_KEY` | آپ کی Gemini API key |
| `GROQ_API_KEY` | آپ کی Groq API key |
| `PROVIDER_ORDER` | `claude,gemini,groq` |

4. تبدیلی محفوظ کریں، پھر **"Deploys" ٹیب → "Trigger deploy" → "Deploy site"** دبائیں (نئی keys لاگو ہونے کے لیے دوبارہ ڈیپلائے ضروری ہے)

> 🔒 یاد رہے: یہ keys صرف Netlify کی Environment Variables میں ڈالیں، کبھی کسی فائل میں لکھ کر GitHub پر اپلوڈ نہ کریں — ورنہ وہ عوام کے لیے کھل جائیں گی۔

## قدم 3 — چیک کرنا

سائٹ کھلنے کے بعد 3-4 سٹاک شامل کر کے "Analyze" دبائیں۔ اگر کچھ غلط ہو تو:

## قدم 4 — لاگ ان سسٹم فعال کرنا (نیا، ضروری)

اب ایپ میں لاگ ان کی سہولت شامل ہے — کوئی بھی خود سے سائن اپ نہیں کر سکتا، صرف وہی جسے آپ دعوت دیں۔

**Netlify Identity فعال کرنا:**
1. Netlify ڈیش بورڈ میں اپنی سائٹ کھولیں
2. اوپر مینیو میں **"Identity"** ٹیب پر جائیں (اگر نظر نہ آئے تو "Site configuration" کے اندر ڈھونڈیں)
3. **"Enable Identity"** پر کلک کریں
4. **"Registration"** کی سیٹنگ میں جا کر **"Invite only"** منتخب کریں (بہت ضروری — ورنہ کوئی بھی سائن اپ کر سکے گا)

**لوگوں کو دعوت دینا:**
1. اسی "Identity" ٹیب میں **"Invite users"** پر کلک کریں
2. ان کی ای میل لکھیں، بھیج دیں
3. وہ اپنی ای میل میں آیا لنک کھول کر پاس ورڈ بنائیں گے، بس ہو گیا

**اپنے آپ کو "ایڈمن" بنانا (تاکہ سب کا پورٹ فولیو دیکھ سکیں):**
1. Identity ٹیب میں اپنی ای میل (جو آپ نے بطور صارف بنائی) پر کلک کریں
2. **"App metadata"** میں یہ لکھیں:
   ```json
   { "roles": ["admin"] }
   ```
3. محفوظ کریں — اب لاگ ان کرنے پر آپ کو "ایڈمن ویو" کا لنک نظر آئے گا

⚠️ **اپڈیٹ (اہم):** پہلے یہ لاگ ان Netlify کے تیار شدہ "ویجٹ" (پاپ اپ iframe) سے ہوتا تھا، جو کچھ کمپیوٹرز/نیٹ ورکس پر لوڈ ہونے میں ناکام ہو رہا تھا۔ اب اس کی جگہ ایک سادہ، خود بنایا ہوا لاگ ان فارم استعمال ہوتا ہے جو براہ راست Netlify Identity کے سرور سے بات کرتا ہے — کسی iframe یا بیرونی script پر انحصار نہیں۔ دعوت (invite) یا "بھول گئے پاس ورڈ" کی ای میل میں جو لنک آئے گا، اسے کھولنے پر بھی یہی اپنا سادہ فارم "نیا پاس ورڈ بنائیں" کے عنوان سے نظر آئے گا۔

**Blobs (پورٹ فولیو ڈیٹا محفوظ رکھنے کے لیے):**
یہ خودکار فعال ہو جاتا ہے، الگ سے کچھ کرنے کی ضرورت نہیں — بس یقینی بنائیں کہ آپ کا Netlify پلان Blobs سپورٹ کرتا ہے (مفت ٹیئر پر بھی عام طور پر شامل ہوتا ہے)۔

⚠️ **اپڈیٹ:** اب یہ حد ختم کر دی گئی ہے — `analyze` اور `intraday` فنکشنز بھی اب سرور کی سطح پر لاگ ان چیک کرتے ہیں۔ بغیر لاگ ان (چاہے براہ راست لنک سے بھی) کوئی بھی حصہ استعمال نہیں ہو سکتا۔ `debug-env` بھی اب صرف ایڈمن کے لیے محدود ہے۔

## قدم 5 — روزانہ خودکار ای میل الرٹ (نیا)

اب ایپ خود بخود روزانہ (پیر تا جمعہ، مارکیٹ بند ہونے کے بعد، تقریباً 3:30 بجے شام پاکستانی وقت) ہر صارف کے پورٹ فولیو کو چیک کرتی ہے اور اگر منافع مقررہ حد تک پہنچے یا فروخت کا اشارہ ملے تو خودکار ای میل بھیج دیتی ہے۔

**Resend.com سیٹ اپ (ای میل بھیجنے کے لیے):**
1. `resend.com` پر مفت اکاؤنٹ بنائیں (کریڈٹ کارڈ درکار نہیں)
2. ڈیش بورڈ میں **"API Keys"** سے ایک نئی key بنائیں
3. Netlify کی Environment Variables میں یہ شامل کریں:
   - `RESEND_API_KEY` → اپنی Resend key
   - `PROFIT_ALERT_PCT` → `10` (یا جتنا فیصد منافع پر مطلع ہونا چاہیں)

⚠️ **ایک اہم حد جو ابتدا میں ہو گی:** نئے Resend اکاؤنٹ پر، جب تک آپ اپنا کوئی ڈومین Resend میں verify نہ کریں، آپ **صرف اپنی ہی وہ ای میل جس سے Resend اکاؤنٹ بنایا ہے** کو میل بھیج سکیں گے — دوسرے صارفین کو نہیں۔ دوسرے صارفین تک ای میل پہنچانے کے لیے:
- Resend ڈیش بورڈ میں **"Domains"** جا کر اپنا کوئی ڈومین (مثلاً `azeemihub.com`) شامل کر کے verify کریں (چند DNS ریکارڈز شامل کرنے ہوتے ہیں، ہدایات Resend خود دیتا ہے)
- اس کے بعد `RESEND_FROM_EMAIL` بھی شامل کریں، مثلاً: `PSX Analyzer <alerts@azeemihub.com>`

**خود ٹیسٹ کرنا:**
اب یہ فنکشن عوام کے لیے کھلا نہیں (پہلے کوئی بھی لنک کھول کر ای میلیں چلوا سکتا تھا)۔ صرف Netlify کا شیڈیولر یا لاگ ان ایڈمن اسے چلا سکتا ہے:
- ایڈمن اکاؤنٹ سے **ایڈمن ویو** کھولیں → **"روزانہ الرٹ چیک (ای میل بھیجے بغیر)"** دبائیں — یہ صرف دکھاتا ہے کہ کس کو کیا ای میل جاتی، کچھ بھیجتا نہیں۔
- **"روزانہ الرٹ ابھی چلائیں"** اصل ای میلیں بھیجتا ہے (پہلے تصدیق پوچھتا ہے)۔
- اگر Netlify یہ بٹن URL کے ذریعے چلنے نہ دے تو Netlify ڈیش بورڈ → **Functions → daily-alert-check → "Run now"** استعمال کریں۔

## اہم نوٹس


- **نیا فیچر — روزانہ ای میل الرٹ:** پورٹ فولیو میں شامل ہر ہولڈنگ روزانہ خودکار چیک ہوتی ہے، منافع کی حد یا فروخت کے اشارے پر ای میل آتی ہے (تفصیل اوپر قدم 5 میں)۔
- **نیا فیچر — خبروں پر مبنی تجزیہ:** جب کوئی سٹاک اپنی 3 ماہ کی کم ترین سطح کے قریب ہو، ایپ خودکار Google News سے اس کمپنی کی حالیہ سرخیاں لاتی ہے (کوئی API key درکار نہیں) اور AI کو دکھا کر پوچھتی ہے کہ آیا یہ خبریں بحالی کی طرف اشارہ کرتی ہیں یا مزید کمزوری کی طرف۔ خبریں "تفصیل" بٹن کے نیچے نظر آئیں گی۔
- **نیا فیچر — رجحان (Trend):** ہر قطار میں پوزیشن کے نیچے 📈 اوپر جا رہا ہے / 📉 نیچے جا رہا ہے / ➡️ برابر — یہ پچھلے 10 دنوں کی موونگ ایوریج کی سمت سے نکالا جاتا ہے، AI کی وضاحت میں بھی یہ شامل ہو گا کہ سٹاک کس طرف جا رہا ہے۔

- **نیا فیچر — 3 ماہ اور 1 سال کی ہائی/لو پوزیشن:** ہر سٹاک کی قطار میں "تفصیل" بٹن دبانے سے دکھے گا کہ سٹاک اپنی 3 ماہ اور 1 سال کی بلند/کم ترین سطح کے کتنے قریب ہے۔ یہ قابلِ اعتماد ہے چونکہ یہ روزانہ کی بند قیمتوں (daily close) پر مبنی ہے۔
- **نیا فیچر — آج کا چارٹ:** یہی "تفصیل" کے نیچے "آج کا چارٹ دکھائیں" بٹن سے لوڈ ہو گا۔ ⚠️ یہ PSX کے ایک **غیر دستاویزی (undocumented)** ذریعے سے آتا ہے (`netlify/functions/lib/psxData.js` میں `fetchIntraday`) — اس لیے **پہلی بار ٹیسٹ کرنے پر ممکن ہے کام نہ کرے یا خالی/غلط ڈیٹا دے**۔ اگر ایسا ہو تو مجھے اسکرین شاٹ یا "Functions" لاگ کا پیغام بھیج دیں، میں اس فائل میں پارسنگ ٹھیک کر دوں گا۔
- **"جب سے لانچ ہوا" ڈیٹا شامل نہیں کیا گیا** — یہ ڈیٹا PSX مفت میں قابلِ اعتماد طریقے سے نہیں دیتا، اس لیے 3 ماہ اور 1 سال والی حد کافی عملی متبادل ہے۔
- **Ollama** اس Netlify ورژن میں کارآمد نہیں (چونکہ یہ کلاؤڈ پر چلتا ہے، آپ کے کمپیوٹر تک رسائی نہیں رکھتا) — اس لیے یہاں صرف Claude → Gemini → Groq کی ترتیب ہے۔ اگر آپ دوبارہ کبھی گھر کے کمپیوٹر پر (Ollama سمیت) چلانا چاہیں تو پہلے والا Python ورژن (`psx-analyzer.zip`) موجود ہے۔
- **ہفتہ/اتوار:** پہلے کی طرح، PSX بند ہونے پر خودکار آخری دستیاب (جمعہ کی) قیمت دکھائے گا۔
- **10 سیکنڈ کی حد:** Netlify کے مفت ٹیئر پر ہر تجزیہ 10 سیکنڈ میں مکمل ہونا چاہیے — چونکہ اب ایک سال تک کا ڈیٹا بھی لایا جا رہا ہے، 3-5 سٹاکس ایک ساتھ رکھیں تو بہتر ہے، 8-10 سٹاکس میں تھوڑی تاخیر ممکن ہے۔
- **آئیکنز:** `public/icon-192.png` اور `public/icon-512.png` شامل ہیں؛ چاہیں تو اپنے آئیکن سے بدل دیں۔

## سیکیورٹی کی خرابیاں جو ٹھیک کی گئیں
- **XSS:** خبروں کی سرخیاں، AI متن اور صارف کے سٹاک کوڈ سیدھے HTML میں جا رہے تھے۔ ایک صارف اپنے پورٹ فولیو میں خراب کوڈ ڈال کر ایڈمن کا لاگ ان ٹوکن چرا سکتا تھا۔ اب ہر جگہ escape ہوتا ہے۔
- **پورٹ فولیو کی جانچ:** سرور اب سٹاک کوڈ، مقدار، قیمت، تاریخ، strategy اور سائز چیک کرتا ہے (پہلے کچھ بھی محفوظ ہو جاتا تھا)۔
- **`daily-alert-check`** عوام کے لیے کھلا تھا — اب صرف شیڈیولر/ایڈمن۔
- **`publish = "."`** کی وجہ سے `package.json`، README اور فنکشنز کا سورس بھی ویب پر کھلا تھا — اب صرف `public/` شائع ہوتا ہے۔
- براؤزر کنسول میں لاگ ان ٹوکن پرنٹ ہو رہے تھے — ختم۔ security headers شامل۔

- ہر بیرونی درخواست پر ٹائم آؤٹ (Netlify کی 10 سیکنڈ حد سے پہلے)، تجزیہ متوازی، AI providers کے لیے بچا ہوا وقت دیکھ کر fallback۔
- پورٹ فولیو صفحہ اب `/api/quotes` استعمال کرتا ہے (AI کے بغیر، 30 سٹاک تک) — پہلے ہر بار AI چلتا تھا اور 10 کے بعد کی ہولڈنگز کی قیمت نہیں آتی تھی۔
- ہر قیمت کے ساتھ **ذریعہ اور تاریخ** (آخری بند قیمت، لائیو نہیں)۔ 30 دن سے کم ڈیٹا ہو تو جعلی نظر آنے والے اشارے دکھانے کی بجائے "ڈیٹا ناکافی" لکھا آتا ہے۔
- RSI کی خرابی: جب کوئی نقصان نہ ہو تو 100 کی بجائے 50 دکھاتا تھا۔
- خبریں: نقل شدہ سرخیاں ہٹتی ہیں، ذریعہ/تاریخ/لنک محفوظ۔
- دو ڈیوائسز: پرانی کاپی سے محفوظ کرنے پر نیا ڈیٹا اوور رائٹ نہیں ہوتا (409 + تازہ ڈیٹا لوڈ)۔ ہٹانے سے پہلے تصدیق۔ ٹوکن ختم ہو تو خودکار تجدید۔
- الرٹ: ای میل کامیاب ہونے کے بعد ہی "بھیج دیا" محفوظ ہوتا ہے، ناکام ہو تو اگلی بار دوبارہ کوشش۔

## Supabase (Phase 2 کی تیاری)
`supabase/migrations/` میں 001 (ٹیبلز)، 002 (RLS: ہر صارف صرف اپنا ڈیٹا؛ ایڈمن صرف پڑھ سکتا ہے)، 003 (انڈیکس)۔ **ایپ ابھی انہیں استعمال نہیں کرتی** — Blobs اور Netlify Identity ویسے ہی چل رہے ہیں۔

RLS تب ہی کام کرتی ہے جب لاگ ان بھی Supabase Auth سے ہو، اس لیے Phase 2 میں لاگ ان اور ڈیٹا ایک ساتھ منتقل ہوں گے، اور Blobs کا پرانا ڈیٹا محفوظ منتقلی کے بعد ہی ہٹے گا۔

**Phase 2 شروع کرنے کے لیے آپ کو:**
1. `supabase.com` پر اکاؤنٹ اور نیا پروجیکٹ بنائیں۔
2. SQL Editor میں `001` → `002` → `003` ترتیب سے چلائیں (کوئی error آئے تو مجھے بھیجیں)۔
3. Project Settings → API سے `SUPABASE_URL` اور anon key نوٹ کریں۔ `service_role` key **صرف Netlify Environment Variables** میں جائے گی — چیٹ، GitHub یا فرنٹ اینڈ میں کبھی نہیں۔

## ٹیسٹنگ

- `node tests/e2e/e2e.js` (اختیاری، Playwright چاہیے) — اصل براؤزر میں 14 مراحل: لاگ ان، پورٹ فولیو، دو ڈیوائس سنک، صارفین کی علیحدگی، XSS، ایڈمن، لاگ آؤٹ۔ 14/14 پاس۔

## ⚠️ ایمانداری سے حدود (جو ابھی ٹیسٹ نہیں ہوئیں)
- میرے ماحول میں انٹرنیٹ نہیں تھا، اس لیے **اصل PSX سائٹ، Netlify Identity/Blobs/Functions، Resend، AI providers اور Supabase** سے ٹیسٹ نہیں ہوا — یہ سب نقلی (fake) جوابوں کے ساتھ ٹیسٹ ہوئے۔ ڈیپلائے کے بعد آپ کی سائٹ پر پہلا حقیقی ٹیسٹ ہو گا۔
- PSX کے صفحات کی پارسنگ پرانی ہی ہے؛ PSX ساخت بدلے یا "آج کا چارٹ" (غیر دستاویزی ذریعہ) نہ چلے تو `netlify/functions/lib/psxData.js` میں ٹھیک ہو گا۔
- SQL فائلیں کسی اصل Postgres/Supabase پر چلا کر نہیں دیکھی گئیں۔
- ابھی **شامل نہیں** (Phase 2–6): Supabase لاگ ان/ڈیٹا، BUY/SELL ٹرانزیکشن ہسٹری، کینڈل چارٹ، بنیادی (fundamental) ڈیٹا، مارکیٹ سکینر، خبروں کی مزید اقسام، قیمت/سپورٹ الرٹس، رسک ڈیش بورڈ، سیکٹر، Shariah، موازنہ، ایکسپورٹ۔

# Phase 2 (Supabase لاگ ان + کلاؤڈ پورٹ فولیو) — کیا بدلا، کیا ٹیسٹ ہوا

اب لاگ ان اور پورٹ فولیو **Supabase** پر ہیں (پہلے Netlify Identity + Blobs تھے)۔ نئے اکاؤنٹس صرف دعوت سے بنتے ہیں۔

## نیا کیا ملا
- **لاگ ان:** ای میل/پاس ورڈ، Supabase خود سیشن تازہ رکھتا ہے۔
- **پورٹ فولیو (`portfolio.html`):** اب BUY/SELL/DIVIDEND/BONUS/RIGHTS/SPLIT کی مکمل ٹرانزیکشن ہسٹری۔ SELL کبھی پرانی BUY نہیں مٹاتی — ہولڈنگ، اوسط لاگت، منافع/نقصان ہمیشہ پوری ہسٹری سے دوبارہ حساب ہوتے ہیں۔
- **واچ لسٹ:** اب کلاؤڈ میں، لامحدود۔
- **ایڈمن ویو:** ہر صارف کا ای میل اور ہولڈنگز اب Supabase سے (RLS کے ذریعے، ایڈمن کی اپنی token سے — کوئی secret key استعمال نہیں ہوتی)۔
- پرانا Blobs کوڈ (`portfolio.js`, `admin-portfolios.js`) حذف نہیں کیا، بس اب کوئی صفحہ اسے نہیں بلاتا — واپسی کے لیے محفوظ ہے۔

## ⚠️ ایمانداری سے حدود
- **کچھ بھی اصل Supabase پر ٹیسٹ نہیں ہوا۔** میرے ماحول میں انٹرنیٹ نہیں تھا، اس لیے:
  - SQL فائلیں (`supabase/migrations/`) کبھی اصل Postgres پر نہیں چلیں۔
  - لاگ ان، پاس ورڈ سیٹ کرنا (دعوت کے لنک سے)، اور Supabase کی اصل API کا ٹھیک ٹھیک طرز عمل — یہ سب میں نے Supabase کی دستاویزات کے مطابق لکھا، مگر اصل سروس کے ساتھ نہیں آزمایا۔
  - `@supabase/supabase-js` لائبریری خود بھی انٹرنیٹ نہ ہونے کی وجہ سے نہیں چلائی جا سکی — میں نے صرف اپنے ٹیسٹ کے لیے اس کا ایک چھوٹا نقلی ورژن لکھا (`tests/e2e/supabase-shim.js`)، اصل لائبریری کبھی نہیں چلی۔
- ٹیسٹ: `npm test` (76 خودکار ٹیسٹ) اور `node tests/e2e/e2e.js` (14 براؤزر مراحل، سب نقلی Supabase کے ساتھ) — دونوں پاس۔ **پہلا حقیقی ٹیسٹ آپ کی لائیو سائٹ پر ہو گا۔**

## آپ کو کیا چیک کرنا ہے (تعیناتی کے بعد)
1. لاگ ان کریں۔
2. ایک BUY ٹرانزیکشن شامل کریں — قیمت اور منافع/نقصان صحیح نظر آنے چاہییں۔
3. اسی اکاؤنٹ سے موبائل پر لاگ ان کر کے دیکھیں وہی ڈیٹا نظر آتا ہے۔
4. ایڈمن اکاؤنٹ سے ایڈمن ویو کھولیں۔
5. جو بھی خرابی یا سکرین شاٹ ملے، مجھے بھیج دیں۔

**اگلے مراحل (Phase 3–6):** کینڈل چارٹ، fundamentals، مارکیٹ سکینر، مزید الرٹس، موازنہ، رسک ڈیش بورڈ، سیکٹر، Shariah، ایکسپورٹ — ابھی نہیں بنے۔
